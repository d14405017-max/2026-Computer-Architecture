# ABSDIFF C baseline 與測資設計報告（CP1）

## 1. 本次目標

說明 ABSDIFF 的 C 參考函式設計及其 32-bit wrap 行為。
整理測試向量與預期輸出，涵蓋一般情況和有號整數邊界。

## 2. 設計內容

### 2.1 語意與函式設計

ABSDIFF 接收兩個有號 32-bit 輸入，先計算 `rs1 - rs2` 的低 32 位元，再對該位元模式取絕對值。結果以 `uint32_t` 表示，方便保留所有 32-bit 結果位元，包括 `0x80000000`。

本組 C baseline 原始碼位於 `instructions/05_ABSDIFF/c_baseline/`，參考函式為 [absdiff_ref.c](../instructions/05_ABSDIFF/c_baseline/absdiff_ref.c)。核心流程如下：

```text
diff = (uint32)rs1 - (uint32)rs2
if diff 的最高位元為 1:
    diff = (~diff) + 1
return diff
```

轉成 `uint32_t` 後進行無號減法，運算依 C 語言規則 modulo `2^32`，避免有號溢位造成未定義行為。若差值最高位元為 1，以二補數取負得到其 32-bit 絕對值。

### 2.2 測資設計

測試檔位於 `instructions/05_ABSDIFF/tests/`，向量檔為 [absdiff_vectors.csv](../instructions/05_ABSDIFF/tests/absdiff_vectors.csv)，共 16 組，含相同數值、正負數排列、最大／最小有號值及 wrap 邊界。預期值欄位使用無號十進位表示結果位元模式。

`INT32_MIN` 的數學絕對值超出有號 32-bit 範圍；本題定義以 32-bit wrap 表示，因此結果位元模式為 `0x80000000`，無號十進位值為 2147483648。

**測試範圍說明：**C 參考程式的 `main` 內建 7 組案例；另有 16 組完整測資與預期輸出的 CSV。CSV 的所有預期值已依公式逐筆核對；本報告不宣稱 C 程式已自動讀取或執行全部 CSV 案例。

## 4. 遭遇的問題與解法

若直接對有號值相減，極值組合可能造成 signed overflow；直接對 `INT32_MIN` 取有號絕對值也無法在 `int32_t` 中表示。實作先轉成 `uint32_t` 做 modulo `2^32` 減法，再用最高位元判斷並以無號補碼取負，讓結果保持為明確的 32-bit 位元模式。

## 5. 白話說明

這個函式先用 32 位元相減，超過可表示範圍的部分會依規則繞回，再把結果轉成不帶正負號的距離。用無號整數計算可以安全處理最小負數，不會因為一般整數溢位而出錯。
