# ABSDIFF CP1／CP2 成果彙整與指令規格、編碼比較（CP3）

## 1. 本次目標

彙整 CP1 的 C baseline 與 CP2 的 RV32IM 實作，確認 ABSDIFF 語意一致。
提出自訂指令編碼，並比較 RV32IM baseline 與單一自訂指令的指令數。

## 2. 設計內容

### 2.1 指令規格

| 項目 | 定義 |
|---|---|
| 指令名稱 | `ABSDIFF` |
| 語意（公式） | `rd = abs32((rs1 - rs2) mod 2^32)` |
| 運算元與定義域 | 二元；`rs1`、`rs2` 是 32-bit 暫存器位元模式，依有號二補數解讀 |
| 結果範圍 | 無號位元模式 `0x00000000` 至 `0x80000000`；`0x80000000` 解讀為有號 `INT32_MIN` |
| 邊界條件與溢位處理 | 先將減法結果限制為低 32 位元，再對該位元模式取絕對值；所有運算均 modulo `2^32`。若差值為 `0x80000000`，取負後仍為 `0x80000000` |

本節規格與 CP1 C baseline 的 `absdiff_wrap32` 及 CP2 RV32IM 函式描述相同，兩者皆先做 32-bit wrap 減法，再依差值的符號取絕對值。相關檔案為 [C baseline](../instructions/05_ABSDIFF/c_baseline/absdiff_ref.c)、[RV32IM 實作](../instructions/05_ABSDIFF/rv32im/absdiff.S) 與 [16 組測試向量](../instructions/05_ABSDIFF/tests/absdiff_vectors.csv)。

#### 虛擬碼

```text
diff = (rs1 - rs2) mod 2^32
if diff[31] == 1:
    rd = (0 - diff) mod 2^32
else:
    rd = diff
```

### 2.2 CP1 C baseline

CP1 的 C 函式以 `uint32_t` 執行無號減法，確保減法按 modulo `2^32` 計算；若差值最高位元為 1，則以 `(~diff) + 1` 取其 32-bit 二補數。此 C 程式是語意與結果的參考實作，不是特定處理器的機器碼。

### 2.3 CP2 RV32IM baseline

現有函式使用 `a0` 傳入 `rs1` 並回傳結果、`a1` 傳入 `rs2`，`t0` 暫存差值：

```asm
absdiff:
    sub   t0, a0, a1
    bge   t0, zero, .Labsdiff_done
    sub   a0, zero, t0
.Labsdiff_done:
    jalr  zero, 0(ra)
```

`sub` 只保留 32-bit 結果；`bge` 對該結果作有號比較；若差值為負，第二個 `sub` 以二補數取負。`jalr` 是函式返回，不屬於 ABSDIFF 運算本身。

### 2.4 自訂指令編碼提案

依課程統一格式使用 R-type 與 `custom-0` opcode (`0001011`, `0x0B`)。課程資料指出 `funct3`、`funct7` 由教師統一分配；目前 ABSDIFF 的分配值尚未在倉庫資料中確認，因此以下兩欄的值是**編碼提案**，提交前須與教師公布的分配核對。

| 欄位 | `funct7` | `rs2` | `rs1` | `funct3` | `rd` | `opcode` |
|---|---:|---:|---:|---:|---:|---:|
| 位元數 | 7 | 5 | 5 | 3 | 5 | 7 |
| ABSDIFF（funct 欄位提案） | `0000000` | 第二來源 | 第一來源 | `000` | 目的暫存器 | `0001011` |

欄位順序為 `[31:25] [24:20] [19:15] [14:12] [11:7] [6:0]`。以下範例以 `rd=x10`、`rs1=x10`、`rs2=x11` 編碼；三個輸入案例使用相同機器碼，運算結果依暫存器內容而異。

| `rs1` | `rs2` | 預期 `rd`（十進位／十六進位） | 欄位值（funct7 / rs2 / rs1 / funct3 / rd / opcode） | 機器碼 |
|---:|---:|---:|---|---|
| 3 | 10 | 7 / `0x00000007` | `0000000 / 01011 / 01010 / 000 / 01010 / 0001011` | `0x00B5050B` |
| -5 | 3 | 8 / `0x00000008` | `0000000 / 01011 / 01010 / 000 / 01010 / 0001011` | `0x00B5050B` |
| `INT32_MIN` | 1 | 2147483647 / `0x7FFFFFFF` | `0000000 / 01011 / 01010 / 000 / 01010 / 0001011` | `0x00B5050B` |

第三組為邊界案例：`0x80000000 - 0x00000001 = 0x7FFFFFFF`（32-bit wrap），結果為 `0x7FFFFFFF`。

## 3. 結果與分析

### 3.1 CP1／CP2 指令數比較

計數方法：**靜態指令數**為組合語言程式片段中不同指令位置的數量；**動態指令數**為一次呼叫實際執行的指令數。CP1 的 C 原始碼沒有指定 RISC-V 編譯器、版本、最佳化參數或編譯後反組譯結果，因此不能從 C 陳述式數推算機器指令數；表中如實標示未取得。可量化的 machine-instruction 比較以 CP2 RV32IM baseline 為基準，並列出假設已實作的單一自訂指令。比較以單次 ABSDIFF 運算為範圍，不含呼叫者的 `jal`；另列函式返回的 `jalr`。

| checkpoint／實作 | 靜態機器指令數 | 動態機器指令數 | 條件分支 |
|---|---:|---:|---:|
| CP1 C baseline 原始碼 | 未取得 RISC-V 編譯後指令，不能由 C 原始碼直接計數 | 未測量 | C 原始碼有 1 個條件判斷；實際分支指令數依編譯結果而定 |
| CP2 RV32IM 運算本體（`sub`、`bge`、條件式 `sub`） | 3 | 2（差值非負）或 3（差值為負） | 靜態 1；每次呼叫執行 1 |
| CP2 RV32IM 函式（含 `jalr` 返回） | 4 | 3（差值非負）或 4（差值為負） | 靜態 1；每次呼叫執行 1 |
| CP3 自訂 ABSDIFF 指令提案（假設硬體支援） | 1 | 1 | 0 |

以 `(3, 10)` 為例，`diff=-7`，CP2 baseline 的 `bge` 不成立，運算本體執行 3 條；以 `(10, 3)` 為例，`diff=7`，`bge` 成立，運算本體執行 2 條。CP1 C baseline 是高階語言參考；若要和 CP2 作精確機器指令數比較，必須使用指定的 RISC-V 編譯器產生組合語言或反組譯，並記錄工具版本與旗標。表格不推論 cycle 或實際效能；自訂指令的 1 條是假設處理器已實作該指令，不代表目前 RV32IM 模擬器已支援此編碼。

### 3.2 測試結果

下列案例與 [測試向量](../instructions/05_ABSDIFF/tests/absdiff_vectors.csv) 一致。參考實作會先做 32-bit wrap 減法，再對其結果取絕對值。

| `rs1` | `rs2` | 預期 `rd` |

## 4. 遭遇的問題與解法

RV32IM baseline 是函式片段，不能直接當作完整程式執行；需由呼叫程式設定 `a0`、`a1` 並呼叫函式。另需區分 32-bit wrap 減法和一般數學上的絕對差：應先截斷減法結果，再依其 32-bit 符號位取絕對值。以 Ripes 呼叫 baseline 測試後，`(3, 10)` 的結果為 7；自訂 opcode 則仍需確認分配及硬體支援。

## 5. 白話說明

ABSDIFF 先用 32 位元做相減，超出範圍的部分會被捨去，再把結果變成非負的大小。組合語言版本會先相減並檢查正負；若為負就反向相減。自訂指令的想法是把這些步驟包成一條指令，但必須先決定編碼並讓處理器或模擬器支援，才能真正執行。
